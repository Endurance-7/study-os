# Software Requirements Specification (SRS)

Version: 1.0

Status: Draft

---

# 1. Introduction

## Purpose

This document defines the functional and non-functional requirements for StudyOS.

StudyOS is a personal learning, career management, and productivity platform designed to help users prepare for higher education, software engineering interviews, certifications, and long-term career goals.

---

# 2. Scope

StudyOS will provide a centralized platform for:

- Learning roadmap
- Daily task management
- Skill tracking
- DSA tracking
- Project showcase
- Notes management
- Bookmark management
- Document management
- Progress analytics

Future versions will include:

- AI Assistant
- Flashcards
- Mock Interviews
- Resume Builder
- Job Tracker
- University Application Tracker

---

# 3. User Roles

Version 1

- Single User (Owner)

Future

- Multiple Users
- Admin
- Mentor

---

# 4. Functional Requirements

## Dashboard

The system shall:

- Display current sprint
- Display overall progress
- Display today's tasks
- Display weekly goals
- Display quick statistics

---

## Roadmap

The system shall:

- Display learning roadmap
- Track progress
- Mark milestones
- Show completed phases

---

## Task Management

The system shall:

- Create task
- Edit task
- Delete task
- Complete task
- Assign priority
- Assign due date

---

## Skill Tracker

The system shall:

- Track technical skills
- Display percentage completion
- Track learning hours
- Store notes

---

## DSA Tracker

The system shall:

- Store problems
- Store platform
- Store difficulty
- Store topic
- Track completion
- Track revision

---

## Project Management

The system shall:

- Create project
- Upload screenshots
- Store GitHub link
- Store Live URL
- Store Architecture
- Store Technologies
- Track progress

---

## Notes

The system shall:

- Create markdown notes
- Search notes
- Categorize notes
- Support code blocks

---

## Bookmarks

The system shall:

- Store useful links
- Categorize links
- Search links

---

## Documents

The system shall:

- Store document checklist
- Track upload status
- Track expiry dates

---

# 5. Non Functional Requirements

The system should be:

- Secure
- Responsive
- Modular
- Scalable
- Maintainable
- Tested
- Documented
- Fast
